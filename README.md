# CAM Video App

Local development of CAM's video production tool. Read `BLUEPRINT.md` before changes and the relevant Next.js documentation in `node_modules/next/dist/docs/` before changing pages or routes. The framework rules live in `AGENTS.md`.

## Safe local workflow

```bash
pnpm install --frozen-lockfile
pnpm db:start
pnpm db:seed
pnpm dev:preview
```

`dev:preview` binds to localhost and forces offline media and brain providers, even if `.env` contains production credentials. Simulation never writes a credit consumption or refund. Its hypothetical costs are stored separately in API-call metadata and `jobs.params.simulatedBilledUsd`.

The old five styles are archived in the database and the source catalogue. They remain available to the explicit offline CLI below for regression checks. The client library and new-production endpoints do not offer them. CAM Clay offers free local previews; its live production gate remains closed.

## New scripts with local scenes and a test voice

After **Frame my request**, the **Your scenes and voice** card lets you choose an installed Mac test voice and import a still image or MP4 for each scene. Inputs save immediately; reloading restores the unconfirmed draft and its media. Review every imported visual, then confirm with **Run free preview**. The existing-film path keeps its recorded Dylan voice and fixed media.

- Daniel (English), Thomas (French) and Carmit (Hebrew) are offered only when listed by the local macOS `say` command. No model download or remote fallback occurs. They are explicitly test voices, not Bram or a final CAM voice. On other operating systems the silent option remains available. English and French have been rendered end to end; Hebrew availability is detected but its pronunciation and visual layout have not been reviewed.
- Each spoken phrase is synthesized separately at 150 words/minute. Only leading/trailing silence is trimmed; its measured duration sets the scene boundaries. The joined WAV contains 0.4 seconds before speech, 0.35 seconds after every phrase, then a 0.65-second tail. Word positions and subtitles remain approximate, not forced alignment. macOS speech-command delimiters are rejected. The output must contain an audible voice. The complete WAV and its timing are checkpointed with hashes: retries reuse the same recording, since repeated OS synthesis can differ slightly and would otherwise invalidate a completed render.
- Uploads accept still PNG/JPEG/WebP or MP4, at most 32 MB, 24 megapixels for images, and 0.2–60 seconds/up to 4K for clips. The request stream is bounded before multipart parsing. Actual bytes are decoded; MIME and filenames are not trusted. Images are normalized to PNG, clips to H.264/30 fps with audio and metadata removed, bounded to 1920 pixels. SVG, animated images and malformed input are refused. Video input protocols are restricted to local files.
- Media are assigned by scene number and pinned with SHA-256 under `storage/imports/<job>/`. Hashes are checked again before rendering. Copies in each attempt make the montage self-contained. Portrait media are contained rather than cropped in a landscape canvas. Clips keep native speed, are trimmed if too long, and hold their final frame if too short. Empty scenes retain the visible placeholder. Imported artwork still requires editorial and subtitle placement review.
- Editing and confirmation share the job lock. Imports cannot modify a confirmed or running job, and no upload/voice route is enabled in live mode. Replacing/removing a visual detaches it from the draft; previous normalized files remain locally for now. Storage cleanup and multi-user authentication are still required before hosting.
- Outputs include MP4, test WAV, SRT/VTT, a provenance report, measured scene timings, approximate word timings and visual check sheets. No paid request is sent and no credit entry is created.

`pnpm test:local-media` exercises the production routes directly, blocks application fetch, imports an image and a short clip containing unwanted audio, rejects invalid media/voice/scene input, verifies draft persistence and confirmation locking, and renders the selected local voice. It checks that clip audio was removed, a short clip is held, narration is audible, captions exist, duplicate execution renders once, and expenses/ledger remain zero. It then simulates interruption after rendering and verifies recovery of the identical voice and cached montage. It also verifies direction persistence without rewriting speech, new end-frame requests, the Bram request identity and the legacy recording's audio ranges, a pending voice quote, and an offline transport rehearsal with zero paid requests. This integration check needs macOS Daniel, FFmpeg and the local database; portable unit tests run with `pnpm test`.

## File transfer, budget caps and Bram synchronization

`media-transfers.ts` uploads only hash-matching references, checkpoints acknowledged URLs and rejects expired/ambiguous uploads. Its transport uses fal CDN v3 initiate + PUT, with credentials sent only to `rest.fal.ai`. It strips credentials from object-storage requests, refuses redirects and limits streams before decoding. Downloads are separate from generation: retries reuse a valid local file, never submit a second generation. Image/video bytes use the existing decoder and normalization, removing metadata and clip audio. Voice files must contain one audible mono/stereo audio stream, last 0.2–600 seconds, and stay below 64 MB. They become 48 kHz mono WAV without changing speed, adding pauses or trimming words. Source and normalized hashes are retained; corruption blocks reuse. The real transfer factory stays behind the same unconditional CAM gate.

`budget.ts` requires a complete quote and approval bound to the exact plan, operation fingerprints and expiry. USD and Higgsfield credits use separate integer millionths. A transaction-scoped PostgreSQL advisory lock serializes reservations across jobs and processes; the state lives in dedicated `settings` keys, separate from customer credit movements. Each budget-wrapped generation/transcription submission consumes its reservation before sending. Unknown outcomes and failures keep the maximum held until cost evidence is reconciled; they are never automatically refunded. Actual costs settle idempotently. Overruns are recorded in full and block further submissions. Explicit cancellation can release only operations never attempted, and released approvals cannot submit later. The store includes an account cap and each approval has a production cap. Real provider cost retrieval is not inferred from queue completion.

The generation bundle now includes a distinct word-level Whisper request after Bram, with `task=transcribe`, `chunk_level=word`, and diarization off. No transcription has been purchased; its quote remains pending in the Studio. The queue journals its ID and transcript. `voice-alignment.ts` checks the script hash, normalized audio hash, every original word, ordered non-overlapping timestamps and the recording duration. Missing/extra/different words, segment-level or null timestamps and a different recording stop for review. Case and punctuation may differ in recognition; captions preserve the original text. This is strict transcript matching, not a local speech recognition model or automatic verification that the speaker is Bram.

A voice approval is bound to the audio, script and alignment hashes. `alignedGenerationPlan` then recalculates scene and clip durations, covering leading silence, pauses and tail without speeding up speech. Changed audio/timing invalidates animation fingerprints and their quotes even when rounded durations match. Clips over 15 seconds remain blocked for splitting. The same timing structure feeds the existing montage and captions. Simulation alignments and approvals cannot validate a final voice.

Every free preview now emits **Budget checks (simulation)**. A preview with a Mac test voice also emits **File transfer & voice sync checks (simulation)**: fake uploads/downloads backed by local character/audio files, normalization, hash checks and a synchronized generation bundle. These QA files are never assigned to new scenes or presented as generated Bram media. Amounts are deliberately artificial, words use the test voice's estimated timing, and final Bram approval stays false. Recovery reuses the transferred bytes and settled simulation budget. The standalone contract tests exercise failures; `pnpm test:local-media` additionally races two actual PostgreSQL reservations, transfers a clip with unwanted audio, renders, resumes and checks zero application fetch attempts/customer debits.

Contracts checked against the installed fal client 1.10.1 (`storage.ts`/`config.ts`) and [Whisper's official schema](https://fal.ai/models/fal-ai/whisper/api). These integration checks use local media only and make no application-process external fetch.

## Recovering interrupted local previews

Reopen the Studio after restarting `pnpm dev:preview`. **Resume free preview** is available for unfinished Clay planning or existing-film jobs in the same offline mode. It never resumes live provider requests. A short five-second grace period allows newly queued jobs to start before offering recovery.

Each worker holds a PostgreSQL session advisory lock and uses that same connection for job state and metering. Read-only polling consults `pg_locks` without taking a lock, so it cannot block a launch. The lock ends with the worker connection; duplicate recovery requests cannot execute the same job together. Recovery moves a failed job back to the confirmed queue before responding, so the browser keeps polling while it starts. See the [PostgreSQL lock representation](https://www.postgresql.org/docs/current/view-pg-locks.html).

Every attempt has an isolated `storage/concepts/<job>/attempts/<attempt>/` folder. The completed render is checkpointed with hashes of the composition, every asset (including voice, fonts and clips), and the output. An unchanged valid checkpoint skips rendering; missing or corrupt files trigger a new local render. A process killed during rendering can only write to its old attempt directory. Quality checks run again before publishing the result. Early preparation steps are recomputed locally; this is a render checkpoint, not paid per-shot request recovery.

```bash
pnpm test:recovery
```

With local PostgreSQL running, this creates a test preview, kills its worker after the render checkpoint, then starts two recovery workers. It verifies one recovery, unchanged cached render, final quality checks, one completed-render meter entry and zero credit movements. Proof: `storage/qa/cam-recovery-proof.json`.

This is explicit local recovery, not an unattended production queue. Durable provider IDs, cross-job budget reservations and spending caps are exercised in simulation. Live reconciliation and automatic background recovery remain unavailable.
