# CAM Video App

Local development of CAM's video production tool. Read `BLUEPRINT.md` before changes and the relevant Next.js documentation in `node_modules/next/dist/docs/` before changing pages or routes. The framework rules live in `AGENTS.md`.

## Safe local workflow

```bash
pnpm install --frozen-lockfile
pnpm db:start
pnpm db:seed
pnpm dev:preview
```

`dev:preview` binds to localhost and forces offline media and brain providers, even if `.env` contains production credentials. Simulation never writes a credit consumption or refund. Its hypothetical costs are stored separately in API-call metadata and `jobs.params.simulatedBilledUsd`.

The old five styles are archived in the database and the source catalogue. They remain available to the explicit offline CLI below for regression checks. The client library and new-production endpoints do not offer them. CAM Clay offers free local previews; its live production gate remains closed.

## Existing CAM characters and voice

In the Studio, choose **Load CAM example**, **Prepare existing film · $0**, then **Rebuild existing film · $0**. The app reconstructs a 52.25-second vertical film from the 12 existing animated clips and the recorded Dylan voice. This is local editing of existing media, not fresh generation. The last confirmed production is restored on reload in the same browser. If the local server stopped during work, the Studio offers **Resume free preview** after restart.

```bash
pnpm dryrun cam-clay 9:16 --existing < tests/fixtures/eyal.txt
```

The checked-in `src/lib/concept/demo/manifest.json` pins 15 files (65.4 MB) under `storage/cam-oct05-v2/concept-1-pate-a-modeler/montage/`. Media remain gitignored. They must be restored separately on another machine; missing or modified files block this mode explicitly. The app verifies all hashes before framing and again when copying the media into a self-contained job folder. It does not fetch missing assets or silently substitute another voice.

The recorded voice is **Dylan / Higgsfield Seed Audio, v3 with breathing pauses**. Its PCM matches `voix/voix-dylan-v3-respire.wav`. Imported timing uses measured silence boundaries with approximate word positions; three collapsed word intervals are repaired within their preceding spoken span, documented in each job's `timing.json`. No new transcription or provider call occurs. Picture speed fits the recorded speech; voice speed stays unchanged. This version uses voice only, without the old music/SFX mix.

The exact script, Clay recipe and 9:16 format are enforced on the server. A different script or format uses the planning path below. Outputs include MP4, WAV, SRT/VTT, media provenance, shot/cut contact sheets and one review frame per subtitle. Every spoken word is captioned, including lines repeated by titles. Caption positions vary by shot to keep faces clear; a human visual review remains necessary. The export checks also reject a missing/inaudible voice. Browser media seeking uses byte-range responses.

Reference run: `884013f5-853e-4952-b9d4-36fe31c741c7`, 207 seconds end to end on this Mac, 1080×1920 / H.264 / AAC / 30 fps, one render under duplicate execution, zero real costs, zero ledger movements and zero application-process fetch attempts. A subsequent visual pass moved captions away from faces in shots 3, 6 and 12.

Outputs include a 1080p MP4, storyboard, exact draft prompts, locked-reference hashes, estimated word timings and contact sheets. Choose 9:16, 16:9 or 1:1 before framing. Each canvas is laid out independently; a single job currently exports only the selected format.

```bash
pnpm dryrun cam-clay 9:16 < tests/fixtures/eyal.txt
```

The reference script keeps its 14 editorial beats and its board-to-phone end frame. Other scripts preserve every word and receive neutral placeholder scenes, not a claimed finished creative storyboard. Previews default to silent audio and placeholder visuals; the local inputs below can replace them. The production sheet is a review artifact, not permission to send requests.

## New scripts with local scenes and a test voice

After **Frame my request**, the **Your scenes and voice** card lets you choose an installed Mac test voice and import a still image or MP4 for each scene. Inputs save immediately; reloading restores the unconfirmed draft and its media. Confirm with **Run free preview**. The existing-film path keeps its recorded Dylan voice and fixed media.

- Daniel (English), Thomas (French) and Carmit (Hebrew) are offered only when listed by the local macOS `say` command. No model download or remote fallback occurs. They are explicitly test voices, not Dylan or a final CAM voice. On other operating systems the silent option remains available. English and French have been rendered end to end; Hebrew availability is detected but its pronunciation and visual layout have not been reviewed.
- Each spoken phrase is synthesized separately at 150 words/minute. Only leading/trailing silence is trimmed; its measured duration sets the scene boundaries. The joined WAV contains 0.4 seconds before speech, 0.35 seconds after every phrase, then a 0.65-second tail. Word positions and subtitles remain approximate, not forced alignment. macOS speech-command delimiters are rejected. The output must contain an audible voice. The complete WAV and its timing are checkpointed with hashes: retries reuse the same recording, since repeated OS synthesis can differ slightly and would otherwise invalidate a completed render.
- Uploads accept still PNG/JPEG/WebP or MP4, at most 32 MB, 24 megapixels for images, and 0.2–60 seconds/up to 4K for clips. The request stream is bounded before multipart parsing. Actual bytes are decoded; MIME and filenames are not trusted. Images are normalized to PNG, clips to H.264/30 fps with audio and metadata removed, bounded to 1920 pixels. SVG, animated images and malformed input are refused. Video input protocols are restricted to local files.
- Media are assigned by scene number and pinned with SHA-256 under `storage/imports/<job>/`. Hashes are checked again before rendering. Copies in each attempt make the montage self-contained. Portrait media are contained rather than cropped in a landscape canvas. Clips keep native speed, are trimmed if too long, and hold their final frame if too short. Empty scenes retain the visible placeholder. Imported artwork still requires editorial and subtitle placement review.
- Editing and confirmation share the job lock. Imports cannot modify a confirmed or running job, and no upload/voice route is enabled in live mode. Replacing/removing a visual detaches it from the draft; previous normalized files remain locally for now. Storage cleanup and multi-user authentication are still required before hosting.
- Outputs include MP4, test WAV, SRT/VTT, a provenance report, measured scene timings, approximate word timings and visual check sheets. No paid request is sent and no credit entry is created.

`pnpm test:local-media` exercises the production routes directly, blocks application fetch, imports an image and a short clip containing unwanted audio, rejects invalid media/voice/scene input, verifies draft persistence and confirmation locking, and renders the selected local voice. It checks that clip audio was removed, a short clip is held, narration is audible, captions exist, duplicate execution renders once, and expenses/ledger remain zero. It then simulates interruption after rendering and verifies recovery of the identical voice and cached montage. This integration check needs macOS Daniel, FFmpeg and the local database; portable unit tests run with `pnpm test`.

## Recovering interrupted local previews

Reopen the Studio after restarting `pnpm dev:preview`. **Resume free preview** is available for unfinished Clay planning or existing-film jobs in the same offline mode. It never resumes live provider requests. A short five-second grace period allows newly queued jobs to start before offering recovery.

Each worker holds a PostgreSQL session advisory lock and uses that same connection for job state and metering. Read-only polling consults `pg_locks` without taking a lock, so it cannot block a launch. The lock ends with the worker connection; duplicate recovery requests cannot execute the same job together. Recovery moves a failed job back to the confirmed queue before responding, so the browser keeps polling while it starts. See the [PostgreSQL lock representation](https://www.postgresql.org/docs/current/view-pg-locks.html).

Every attempt has an isolated `storage/concepts/<job>/attempts/<attempt>/` folder. The completed render is checkpointed with hashes of the composition, every asset (including voice, fonts and clips), and the output. An unchanged valid checkpoint skips rendering; missing or corrupt files trigger a new local render. A process killed during rendering can only write to its old attempt directory. Quality checks run again before publishing the result. Early preparation steps are recomputed locally; this is a render checkpoint, not paid per-shot request recovery.

```bash
pnpm test:recovery
```

With local PostgreSQL running, this creates a test preview, kills its worker after the render checkpoint, then starts two recovery workers. It verifies one recovery, unchanged cached render, final quality checks, one completed-render meter entry and zero credit movements. Proof: `storage/qa/cam-recovery-proof.json`.

This is explicit local recovery, not an unattended production queue. Paid request IDs, cross-job budget reservations, spending caps and automatic background recovery still need implementation.

## Verification

```bash
pnpm test
pnpm lint
PROVIDER_MODE=dryrun BRAIN_MODE=mock pnpm build
pnpm check:providers
```

Provider diagnostics perform an Anthropic model lookup, upload one dummy byte to fal storage, and optionally read Runway's organization endpoint. They do not generate text, images, audio or video. Failure exits nonzero. Passing only proves the specific access checked, not sufficient credits, inference availability or media quality.

Offline end-to-end regression, with PostgreSQL running and recipes seeded:

```bash
pnpm dryrun cartoon-ink-noir 9:16 <<'SCRIPT'
A book opens. The pages reveal the full context. Read the whole passage before sharing a claim.
SCRIPT
```

This blocks Node fetch, submits the same job twice concurrently, renders a placeholder MP4 and writes a production sheet. It fails if the job fails, makes an external fetch, renders twice, records real expenses or writes any ledger entry. This is a technical regression check, not a CAM visual-quality demonstration. The retired collage renderer still loads its animation library externally; its offline rendering will be replaced with the concept engine.

## Production mode

`PROVIDER_MODE=fal` enables real media adapters. `BRAIN_MODE=api` enables the Anthropic brain in real mode. `VIDEO_PROVIDER=runway` changes only the video adapter. Keep secrets in the gitignored `.env` file; `.env.example` lists the configuration.

A paid test still requires Shimon's approval of its script, style, voice and estimated budget. No paid generation is part of the development checks above.

A production snapshots its execution mode. Confirmation and execution refuse a mode change, archived styles cannot be confirmed, and duplicate confirmations/executions are claimed atomically. The successful job update and the credit debit share one transaction. Local concept previews can now be recovered explicitly. Durable paid-provider resumption, budget reservations between different jobs, price caps and complete provider metering remain work for the concept engine.
