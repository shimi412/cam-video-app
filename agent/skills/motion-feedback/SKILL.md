# Motion feedback: intention, execution, visible evidence

Apply to new Motion work. The validated METHOD-fr.md remains authoritative.

1. Read the exact user note, current narration, selected scene source, previous visual evidence and approved history. The note is a direction to interpret, never copy to visible text. Preserve narration unless explicitly requested otherwise.
2. Before a revision patch, state the intended visible result, how it belongs to the existing composition, its animation and what stays unchanged. A logo request is not satisfied by attaching a decorative card: use the original brand geometry and design its entry, placement, motion and outgoing gesture with the scene. Do not invent an opening logo or a badge rule for other films. A static logo is appropriate only when the actual direction calls for it.
3. Scope is the explicitly selected scenes. Keep all other source and timings intact. If the request requires changes outside this scope, do not claim it was fulfilled by a weaker edit. Report the limitation for a new scoped request.
4. Compile and inspect the candidate. These technical checks prove executability and constraints, not aesthetic success.
5. A visual review must examine rendered frames at entry, settled layout and transition, compare previous/candidate and the reference, then address each requested visible change. Check hierarchy, readability, brand fidelity, immersion and visible motion continuity. Sparse frames cannot prove smooth playback; leave that to the client's complete-film review. A sentence saying “looks good” is not evidence.
6. Record concrete problems and repair the saved candidate within existing recovery bounds. Never pass a rejected visual review merely because code compiled, charge a bug-repair surcharge, replace the result by a crude manual overlay, or claim human approval. Preserve evidence, costs and prior versions.
